# Установка юнита

Что нужно одному телефону, прежде чем его можно принять в парк. Каждый шаг
здесь выполнен на первом юните (`lisa`, модель 2109119DG); цифры — то, что
устройство сообщило на самом деле, а не то, что предсказывает документация.

> Русский перевод [install.md](./install.md). Исходная английская версия — основная.

## 1. LineageOS

Следуйте [вики устройства](https://wiki.itsvixano.me/devices/lisa/install/). Две
вещи, о которых она не говорит, и обе стоят времени на первой попытке:

**Прошивайте образы recovery из fastbootd, а не из fastboot загрузчика.**
Загрузчик на этом устройстве почти не отвечает на `getvar` и наотрез отклоняет
передачу 192 МБ:

```text
Sending 'boot' (196608 KB)  FAILED (remote: 'Requested download size is more than max allowed')
```

fastbootd сообщает `max-download-size: 0x10000000` (256 МБ) и принимает её.
Размеры разделов точно совпадают с опубликованными образами — `boot_a` 192 МБ,
`vendor_boot_a` 96 МБ, `dtbo_a` 24 МБ, — поэтому несовпадение здесь означает не
тот билд, а не не тот флаг.

```sh
adb reboot fastboot
fastboot flash boot boot.img
fastboot flash vendor_boot vendor_boot.img
fastboot flash dtbo dtbo.img
```

**Остановка `adb sideload` на 47 % — это успех.** Ожидаемый вывод такой:

```text
serving: 'lineage-23.1-...-lisa.zip'  (~47%)
adb: failed to read command: Success
```

Код возврата 1 приходит от того, что adb рвёт сокет, а не от установки.
Устройство A/B: sideload пишет в неактивный слот и переключается, поэтому юнит,
прошитый на слоте `a`, загружается в слот `b`.

## 2. Magisk

Батарейный guard пишет в `/sys/class/power_supply/battery/`, куда пользователю
shell — `Permission denied`, так что root не опционален.

Обычный путь — патчить `boot.img` в UI приложения Magisk. Для этого нужен
человек, тапающий по телефону, который живёт в стойке, поэтому # question "Для этого нужен
человек, тапающий по телефону, который живёт в стойке, поэтому " это чё за прикол?)))
`scripts/install-magisk.sh` управляет `magiskboot` напрямую тем же
`boot_patch.sh`, который запустило бы приложение:

```sh
./scripts/install-magisk.sh ~/Downloads/lisa-lineage/boot.img
```

```sh
adb reboot fastboot
fastboot flash boot ~/Downloads/lisa-lineage/magisk_patched.img
fastboot reboot
```

`boot_patch.sh` на этом железе трижды печатает `Failed to patch`. Это
специфичные для Samsung hexpatch'и ядра (RKP, defex, `skip_initramfs`); они
никогда не совпадают с ядром Qualcomm, и скрипт считает их необязательными.
Значение имеют строки:

```text
- Stock boot image detected
- Patching ramdisk
- Pre-init storage partition: sda24
Dumping cpio: [ramdisk.cpio]
```

После патча ramdisk становится *меньше* (1714119 → 1622983 байт), потому что
Magisk перепаковывает его с полезной нагрузкой, сжатой xz. Это нормально.

После перезагрузки один раз откройте приложение Magisk, чтобы завершить
настройку.

**Magisk показывает запрос на экране телефона при первом же обращении за root**
и отклоняет его, если никто не ответит. На стоечном юните это выглядит ровно
как сломанный инструмент, поэтому выдайте права один раз и сделайте их
постоянными:

**Magisk app → Superuser → Shell → Granted**

Именно поэтому `rackphone install` печатает предупреждение перед своим первым
обращением за root.

Сохраните стоковый `boot.img`. Его восстановление и есть вся процедура отката.

## 3. Параметры разработчика

Нужно включить на телефоне один раз:

- **Настройки → О телефоне →** семь раз тапнуть по *Номеру сборки*
- **Для разработчиков → Отладка по USB**
- **Для разработчиков → Отладка с root-правами** — сборки LineageOS
  `userdebug` разрешают `adb root` без Magisk, но только с этим пунктом

## 4. Инвентаризация

Запускается один раз на устройство и повторно после каждого обновления
LineageOS. Модули написаны под реальные ноды sysfs, а обновление вендорского
ядра может их сдвинуть или убрать:

```sh
./scripts/inventory.sh
```

Что сообщил первый юнит:

| Параметр | Значение |
| --- | --- |
| Тепловые зоны | 89 |
| `power_supply` | `battery`, `usb`, `wireless` |
| `battery/` пользователю shell | `Permission denied` |
| Счётчик заряда | 3126812 мкА·ч |
| Максимальная ёмкость | 3140000 мкА·ч |
| Проектная ёмкость | 4250000 мкА·ч |
| Состояние здоровья | 74 % |
| Число циклов | 1385 |
| Управление зарядом | `/sys/class/qcom-battery/input_suspend` |

Находка про управление зарядом — та, что оказалась важной. У этого ядра **нет
ни `input_suspend`, ни `battery_charging_enabled` внутри `power_supply`** —
документация по другим устройствам Qualcomm утверждает обратное. Обе рабочие
ноды лежат в `/sys/class/qcom-battery/`, а `power_supply/battery/` предлагает
только `charge_control_limit` (индекс шага 0–16, а не бинарный флаг). Guard
прощупывает систему в рантайме и записывает значение resume обратно, чтобы
убедиться, что нода не просто существует, а действительно учитывается: часть
ядер экспортирует ноды, которые молча игнорируют запись.

## 5. Модули

Соберите и прошейте в Magisk, core первым — плагины без него прерываются:

```sh
./scripts/build-modules.sh
```

## 6. Принятие в парк

```sh
uv run --project cli rackphone adopt lisa01 --label "rack unit 1"
uv run --project cli rackphone deploy lisa01
uv run --project cli rackphone status
```

## Питание

Порт USB 2.0 гарантирует 500 мА, USB 3.x — 900 мА, тогда как этот телефон
договорился на `Max charging current: 1700000` (1,7 А) с той зарядкой, на
которой его тестировали. Один юнит на хорошем порту USB 3.x обычно проходит,
двум нужен powered-хаб с собственным блоком питания. Проверяйте, а не
предполагайте:

```sh
uv run --project cli rackphone metrics | grep -E 'battery_(capacity|current)'
```

Если под нагрузкой при воткнутом кабеле заряд падает, порт не тянет
потребление. Powered-хаб заодно удерживает телефоны живыми через перезагрузку
хоста, которую часть плат обрабатывает снятием питания с USB.
