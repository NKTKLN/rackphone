# Контракт плагина

Модуль Magisk становится плагином Rackphone, поставляя каталог `rackphone/`.
Больше его ничто не регистрирует: `rackphone-core` находит плагины, сканируя
`/data/adb/modules/*/rackphone/plugin.json` при каждом вызове, и учитывает
собственный маркер `disable` от Magisk, поэтому выключенный в Magisk модуль
пропадает и из CLI.

Идентификатор плагина — это идентификатор модуля без префикса `rackphone-`,
поэтому настройки читаются как `battery.max_percent`, а не повторяют
пространство имён.

> Русский перевод [modules.md](./modules.md). Исходная английская версия — основная.

## Файлы

| Файл | Обязателен | Контракт |
| --- | --- | --- |
| `rackphone/plugin.json` | да | Объявление: настройки, действия, ключи статуса |
| `rackphone/defaults.env` | да | `key=value`, генерируется из `plugin.json` |
| `rackphone/metrics.sh` | нет | Экспозиция Prometheus в stdout |
| `rackphone/status.sh` | нет | Строки `key=value` в stdout |
| `rackphone/action.sh` | нет | Вызывается как `action.sh <action-id>` |
| `rackphone/reload.sh` | нет | Вызывается после того, как `rackphone set` затронул этот плагин |

`defaults.env` генерируется, а не пишется руками. CLI валидирует по
`plugin.json`, поэтому дефолт, разошедшийся с объявлением, был бы багом,
заметным только на устройстве без развёрнутого конфига.

## Объявление

```json
{
  "id": "battery",
  "name": "Battery Guard",
  "description": "Keeps the pack in a charge window.",
  "settings": [
    {
      "key": "max_percent",
      "type": "int",
      "default": "80",
      "min": 30,
      "max": 100,
      "label": "Stop charging at",
      "unit": "%",
      "help": "Why this value, not what it is."
    }
  ],
  "actions": [ { "id": "resume", "label": "Resume charging now" } ],
  "status": ["guard", "capacity", "suspended"]
}
```

| Поле | Типы | Примечания |
| --- | --- | --- |
| `type` | `bool`, `int`, `enum`, `string` | Управляет и валидацией, и отрисовкой |
| `min` / `max` | только `int` | Проверяется на хосте до любой записи |
| `values` | только `enum` | Допустимое множество |
| `unit` | любой | Суффикс, показываемый в `rackphone config` |
| `help` | любой | Показывается, когда валидация отклоняет значение |
| `depends_on` | любой | Другой ключ, от которого зависит этот |

`status` перечисляет ключи, которые `status.sh` вправе выдавать, в том порядке,
в котором их показывает CLI.

## Разрешение настроек

Прочитать настройку внутри плагина — значит проверить три места по порядку:

```sh
value=$(getprop "persist.rackphone.$PLUGIN.$key")
[ -z "$value" ] && value=$(sed -n "s/^[[:space:]]*$PLUGIN\.$key=//p" /data/adb/rackphone/config.env | tail -1)
[ -z "$value" ] && value=$(sed -n "s/^[[:space:]]*$key=//p" "$MODDIR/rackphone/defaults.env" | tail -1)
```

Оба поставляемых плагина заворачивают это в `cfg()` / `rp_cfg()`. Читайте
настройки в начале каждой итерации цикла, а не один раз на старте: именно это
позволяет изменению вступить в силу за один интервал опроса без `reload.sh`.

## Как писать metrics.sh

Три правила, каждое вынесено из этого железа:

**Отбрасывайте недоступные показания.** Android кодирует «нет значения» как
`Integer.MAX_VALUE` (`2147483647`). Его экспорт ставит на каждую панель всплески
на 2,1 миллиарда. Отсутствующий ряд честен; `MAX_VALUE` — нет.

**Один проход awk на источник.** У устройства 89 тепловых зон и 8 ядер. Один
`cat` на атрибут — это ~200 форков на скрейп. Читайте много файлов из одного awk
через `getline`.

**Всё дорогое прячьте за настройку.** `dumpsys` стоит примерно 150 мс, а это
почти весь бюджет скрейпа при интервале в 10 секунд.

Выдавайте `# HELP` и `# TYPE` для тех метрик, которыми владеет ваш плагин, и
только для них: core склеивает вывод плагинов дословно, поэтому два плагина,
выдающие одно семейство, породили бы дубликат, который Prometheus отвергнет.

## Страховка от собственного отказа

Если плагин может оставить устройство в состоянии, требующем отката, откатывайте
его на каждом пути выхода. Батарейный guard ловит `INT TERM EXIT`, чтобы
возобновить зарядку, один раз возобновляет её на старте на случай, если
предыдущий запуск убили посреди приостановки, и принудительно возобновляет ниже
защитного порога независимо от конфигурации. Он также пробует *все* кандидатные
ноды управления при возобновлении, а не только выбранную, потому что устаревший
закешированный метод никогда не должен становиться причиной, по которой юнит не
может зарядиться.
