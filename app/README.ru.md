# Rackphone Companion

Приложение-компаньон юнита: APK с разрешением `SEND_SMS`, которым управляет
root-шелл через броадкасты. Полное описание — в [README.md](./README.md); этот
файл существует, чтобы у приложения был свой readme на русском.

> Русский перевод [README.md](./README.md). Исходная английская версия — основная.

Оно нужно потому, что **из-под root отправить SMS нечем**: у `cmd phone` нет
подкоманды отправки, а до биндера `isms` можно достучаться только сырым номером
транзакции, который меняется от версии Android к версии. Приложение с
разрешением — поддерживаемый путь, поэтому оно делает ровно это и ничего больше.

Раз такое приложение всё равно нужно, приём живёт в нём же: `RECEIVE_SMS` отдаёт
сообщение уже разобранным, и схема `mmssms.db`, которую читал прежний
shell-коллектор, перестаёт быть проблемой проекта. Пришедшее складывается в спул,
а хост забирает его тем же контрактом drain/ack.

Второе, ради чего оно существует: **keepalive**. Оператор может отобрать SIM,
которой никто не пользуется, а телефон в стойке с выключенным экраном месяцами
не создаёт ни одного тарифицируемого события. Приложение само, по своему
расписанию, отправляет одно сообщение — себе или на заданный номер, **на каждую
SIM отдельно**: оператор видит только свою, поэтому активность одной ничего не
говорит о другой.

```sh
task app-install    # собрать, поставить и выдать разрешения без единого тапа
task app-test       # тесты Dart
```

Проверено на железе: собрано, установлено с `pm grant`, `SETUP` выдал токен,
`STATUS` ответил `ready`, а `SEND` дошёл до реального телефона — `queued` в
ответе и `ok` в outbox через секунду.

> [!IMPORTANT]
> Кавычки нужны для шелла **на телефоне**, а не только для своего:
> `adb shell am broadcast … --es body 'привет тебе'` отправит только `привет`.
> Оборачивайте всю удалённую команду в двойные кавычки.

Настройка и полный список броадкастов — в [README.md](./README.md).
